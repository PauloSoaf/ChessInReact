## 1. Architectural Overview & Component Topology

Spec 09 resolves the massive data scalability problem inherent in large-scale procedural and variant chess matches. By discarding heavy raw full-state snapshots in favor of the **Event Sourcing** paradigm (procedural initial seed + compact chronological move tape), combined with dictionary compression for extended games, the platform maintains an average match footprint of $< 5\text{ KB}$ in PostgreSQL. This allows the system to store $> 120.000$ completed games within Supabase's 500 MB free tier.

## 2. Implemented Subsystems & Modules

### 2.1 Prisma Schema & Database Modeling (`/prisma/schema.prisma`)
- **`User` Model:**
  - Stores identity, unique username, optional email, and `ratingsMap` JSONB dictionary keyed by `variantId`.
  - Links to `PlayerRating` records and community `CustomVariant` definitions.
- **`PlayerRating` Model (RF-06, RF-12):**
  - Isolates $(Rating, RD, \sigma)$ tuples per player per variant.
  - Compound unique constraint `@@unique([userId, variantId])`.
  - Compound B-Tree descending index `@@index([variantId, ratingValue(sort: Desc)])` supporting sub-25ms leaderboard queries.
- **`MatchHistory` Model (RF-01, RF-02, RF-03, RF-10):**
  - Unique match UUID generated by Matchmaker.
  - Metadata JSON storing procedural seed, topology, and time controls.
  - Chronological linear move stream (`moveStream String[]`).
  - Optional LZ-dictionary compressed byte payload (`compressedPayload Bytes?`) for matches $> 50$ moves.
  - Semantic `engineVersion` tag (default `"1.0.0"`) ensuring backward compatibility.
- **`CustomVariant` Model (RF-08, RF-09):**
  - Stores user-created Betza notation strings and GLTF asset URLs.
  - Implements soft deletion (`deletedAt DateTime?`), ensuring historical replays referencing customized pieces remain functional forever.

### 2.2 Event Sourcing & Compression Engine (`/src/core/persistence/eventsourcing`)
- **`MatchEventStreamEngine.ts`:**
  - `createStream()`: Initializes deterministic stream with seed and engine version.
  - `appendEvent()`: Appends chronological ply entries.
  - `exportAsLinearTape()`: Generates compact algebraic tape (e.g. `"e2>e4@1200"`).
  - `compressStream()`: Automatically applies dictionary tokenization and index encoding when ply count exceeds 50 moves.
  - `decompressStream()`: Reconstructs exact event stream with 100% determinism.
- **`SupabaseRLSPolicyCatalog.ts`:**
  - Authoritative Row Level Security definitions protecting user private emails (`user_read_own_private`), restricting mutation (`user_update_own_profile`), and hiding soft-deleted variants (`variants_read_public_or_own`).
  - Automated DDL generator `generatePostgresMigrationSql()`.
- **`UserStatsAggregator.ts` (RF-14, RNF-13):**
  - Aggregates lifetime stats: total games, wins, losses, draws, win percentage, play duration, and average CAPS2 accuracy.
  - Granular breakdown per variant.
  - LGPD/GDPR anonymization routine replacing personal identifers with anonymous tokens.

### 2.3 Deterministic Replay & PGN Parser (`/src/core/persistence/pgn`)
- **`PGNExporter.ts` (RF-05):**
  - Generates FIDE-compliant Seven Tag Roster PGN text with custom headers (`Variant`, `Topology`, `Seed`, `PlyCount`).
  - Supports standard SAN notation, drops (`@`), and check/checkmate glyphs.
- **`PGNParser.ts` (RF-05):**
  - Parses PGN text into structured metadata headers and sequential move tokens.
- **`ReplayEngine.ts` (RF-04, RNF-07, RNF-11):**
  - Evaluates PGN move stream sequentially, executing `MovePieceCommand` against the ECS domain state.
  - Resolves standard algebraic notation, disambiguation, castling, en-passant, and pawn promotions.
  - Caches sequential snapshots for $O(1)$ random scrubbing and 60 FPS slider playback.

### 2.4 Write-Behind Repository & Glicko-2 ACID Updates (`/src/core/persistence/database`)
- **`MatchRepository.ts`:**
  - `saveMatch()`: High-performance insert attaching metadata and LZ-compressed payloads.
  - `getMatchById()`: Direct retrieval for replay initiation.
  - `listUserMatches()`: Paginated user history query responding in $< 50\text{ms}$.
  - `updateRatingsTransaction()`: Encapsulates Glicko-2 rating recalculations for all match participants inside `prisma.$transaction`, guaranteeing strict ACID isolation.
  - `getLeaderboard()`: Queries top players by variant ordered by rating value descending in $< 25\text{ms}$.
  - `softDeleteVariant()`: Sets `deletedAt` without physical row deletion.
  - `purgeAbandonedSessions()`: Removes abandoned games ($< 2$ moves) older than 7 days.
- **`IPrismaDatabaseClient.ts`:**
  - Strongly typed client contract ensuring testability with mock database adapters and compatibility with production Prisma clients.

## 5. Architectural Invariants Preserved

1. **Free Tier Storage Invariant:**
   - Average storage footprint per game remains $< 5\text{ KB}$, safely supporting $> 100.000$ games within Supabase's 500 MB quota without hosting costs.
2. **Replay Immutability Invariant:**
   - Custom variants deleted by creators remain preserved in historical replays through soft delete (`deletedAt IS NOT NULL`).
3. **Lossless Roundtrip Determinism:**
   - Any match serialized into the Event Stream and decompressed reproduces an identical move tape with zero data distortion.
